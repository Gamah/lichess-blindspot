| 45 | Opening-book cancellation is gone: `explorer.lichess.ovh` answers 401 to a browser on an ordinary connection as well as to this host, and lila's own frontend calls it with `credentials: 'include'` — a lichess session cookie a static page on another origin cannot have. Bring it back only if a way to call it without a lichess session appears; the code is in git, one commit before this row was written. |
| 75 | A game skipped because the engine could not start is recorded in `meta.fetched` — "looked at, found nothing" — and so is never analysed again, even once there is an engine. A session with no engine therefore walks backwards through someone's whole history stamping it, silently, and the deck never fills. Seen for real on a phone: 70 games. The isolation fix makes the engine-less load rarer but not impossible — a dropped 15 MB net download does it too, and `App.engine()` caches that failure for the session. Fix: a separate `meta.needsEngine` list, re-queued from IndexedDB when an engine appears, and stop paging further back while that backlog grows. |
| 90 | **Derive puzzles instead of storing them.** Today a `Puzzle` record is persisted per candidate, so every change to what a puzzle contains needs a migration — `App.withIntro` exists solely to backfill the opening animation onto records written before it. Store the expensive thing instead: the eval array, written back into the stored game's own `analysis` field (lichess' if it analysed the game, ours if we did), and build puzzles as a view over it whenever they are wanted. Puzzle identity is already `gameId:ply`, which is stable under any shape change, so `solve:` records survive untouched. Shape of the work: `src/deck/derive.ts` with a pure `puzzlesFromGame(game, username, {maxPerGame})` doing povOf → variant check → replay → findCandidates → cap → buildPuzzles; `Pipeline.analyse` writes analysis onto the game and emits derived puzzles rather than calling `putPuzzles`; `Profile.games()` replaces `puzzles()`, with `legacyPuzzles()` reading the old `puzzle:` keys so no existing deck is lost; `App.begin` builds the deck from stored games; `withIntro` is deleted. Two consequences to handle: a stored game now contains engine time and must never be purged automatically (`purgeIfTight` is already gone; the Settings row must say deleting games deletes their positions), and "positions per game" becomes retroactive — changing it should rebuild the deck rather than apply only to games analysed afterwards, which is the better behaviour and worth saying in the hint text. A half-finished attempt is in `git stash` as "storage/deck refactor, mid-flight"; it predates the blocked-storage work and will conflict, so it is worth reading for the derive.ts sketch and otherwise redoing. |
