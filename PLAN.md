| 60 | **Rework how games are pulled, and give it a UI.** Today `Pipeline.fetchBatch` has one cursor, `meta.until`, and it only ever moves *backwards* (`until = oldest - 1`); `exhausted` latches the first time a batch comes back empty. So a returning player's **newly played games are never fetched** — the pipeline has paged past the newest game it ever saw and has no way forward. That is the bug half. The feature half: `BATCH` is a hardcoded 20, and `maxGames` is a *cap on what is kept*, not a statement of how far back to look, so there is no way to say "the last 100 games" or "since June" or "just this month's". Wanted: a second cursor (`newest`, the createdAt of the newest game held) used with the export's `since` for a forward refresh at session start, with `until` kept for reaching further back; a "how far back" control (a count, or a date, or "everything") and a "how much at a time" control in Settings; and `exhausted` split into "no more *older* games" and "nothing new since last time", which are different sentences on the exhausted screen. Constraints, all documented in CLAUDE.md and none of them optional: one concurrent export per IP, the `EXPORT_GAP` governor exists because the deck asks for more on every thin solve, a leaked stream locks the address out for an hour, and **do not probe the by-user export from this host** — `test/pipeline.test.ts` fakes the fetch and is where this gets verified. `Store` (the `Pick<Profile, …>` at the top of pipeline.ts) will need widening. **This is also what would bring back a per-position delete.** Delete was built and removed (see CLAUDE.md) because deleting a game loses the analysis *and* the game: `until` has paged past it and `meta.analysed` still names it, so it never comes back. Once a game can be deliberately re-fetched — by id through `/game/export/{id}`, which has no concurrency limiter at all — deleting one costs only the engine time, which is a trade someone can reasonably choose. Whatever does it must drop the id from `meta.analysed`/`meta.fetched` as well, or the game is fetched and then ignored forever. |

Worth scaling the margin by the headroom the position actually has, so that beating a -9 blunder by a hair is not a win. Only 3% of candidates are free wins at all, so measure whether this is worth doing before doing it. |
