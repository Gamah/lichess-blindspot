| 55 | **Deliberate re-fetch of one game, by id — and the per-position delete it unlocks.** Now that the pipeline has a forward cursor and a "how far back" dial, the one thing still unreachable is a *specific* game that has been dropped: `meta.analysed`/`meta.fetched` still name it, so the paging skips it forever, and `purgeGames`/`forgetGame` leave those lists untouched. Delete was built and removed (see CLAUDE.md) for exactly this — deleting a game lost the analysis *and* the game. `/game/export/{id}` has **no concurrency limiter at all** (unlike the by-user export), so one game can be pulled back on demand without touching the one-per-IP budget the batches live under; `fetchGames` would need a sibling that takes an id, and whatever deletes must drop the id from both lists or the game is fetched and then ignored forever. With that, deleting a game costs only the engine time, which is a trade someone can reasonably choose, and per-position delete becomes honest. |

Worth scaling the margin by the headroom the position actually has, so that beating a -9 blunder by a hair is not a win. Small: it is one expression in `judgeEval` and it touches nothing stored, so it is retroactive and free to tune. Do **not** solve this by withholding positions — that was row 65, and it would delete the most instructive puzzles in the deck. Only 3% of candidates are free wins at all, so measure whether this is worth doing before doing it. |
